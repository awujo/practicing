# Audit: taught rules vs the code that claims to implement them

Requested 2026-09-22: go through everything taught and the code logic,
and find bugs or places where Bishop or 4th man have been mis-read into
code.

Read against `SLK_SPEC.md`. Two real bugs found and fixed; five
divergences found and left in place with reasons; one duplication of
work that already existed.

---

## Fixed

### B1. Three triggers shared one stop rule, silently

The stop-loss block ended in `else:  # candidate.trigger ==
"fourth_man"`. True when there were two triggers, false the moment
three more were added without touching that block. `open_close`,
`breakout` and `sweep_break` were all labelled `fourth_man` and given a
stop derived from a sweep extreme that, for a breakout, does not exist.

Nothing failed. The trades appear in the log as `fourth_man` and the
numbers look plausible. This is the same failure shape as the
2026-09-02 A/B that read as a verdict on zone stops and had actually
measured "take only plug-and-play trades".

Each trigger now has its own branch and an unknown one raises.

### B2. The touch gate switched off the two highest-rated triggers

A breakout closes beyond the **minor swing high**, which sits above the
key level (SLK_SPEC 5.4 — he marks it at 1.86789 against a key level at
1.86700). The break candle therefore does not span the key level. The
entry loop gated every trigger on the trigger candle spanning it.

Measured on a synthetic leg: `breakout_entry()` returns True at the
break, the gate returns False.

Both new triggers were disabled by a condition their geometry cannot
satisfy, and the A/B would have reported "the taught triggers find
fewer setups". The gate now has a `window` reading — price must reach
the level, the confirmation may come later — and which reading applies
is **derived** from the trigger set, because the wrong pairing fails
silently.

## Already existed, under other names

### D1. video-14's three confirmations were implemented before I started

`classify_entry_pattern()` is the same three-variant model:

| SLK_SPEC | existing name |
|---|---|
| 5.1 engulf -> direct mitigation | `EntryPattern.DIRECT_MITIGATION` |
| 5.2 engulf + broken open-close | `EntryPattern.NESTED_DISRESPECT` |
| 5.3 engulf -> next candle is inducement | `EntryPattern.FRESH_IRL_REQUIRED` |

So `open_close_disrespect_entry()` re-implements 5.2, and my mapping of
5.3 onto `fourth_man` was loose — `FRESH_IRL_REQUIRED` is the closer
match, and it is the one that carries the "next candle becomes internal
range liquidity" idea explicitly.

Not harmful, but the spec should say this and did not. Corrected there.

## Divergences, left in place

### D2. 5.3 is implemented and turned off

`FRESH_IRL_REQUIRED` only does anything when `irl_mode` is `"skip"` or
`"wait"`. It defaults to `"ignore"`, and `live_flags.py` does not set
it — so the inducement variant never fires in production.

`irl_mode="wait"` is 5.3 almost exactly: wait for that candle's extreme
to be swept, then enter. Untested against the fixed engine.

### D3. The whole classification hangs off the wrong engulfing

`classify_entry_pattern()` runs on the candles following the **engulfing
candle**, where "engulfing" is `is_engulfing()` — the classic
candlestick pattern that appears nowhere in either course. So a
correct three-variant model is anchored to a trigger the source does
not teach.

This is the single largest structural divergence and it is what
`compare_triggers` exists to measure. Not fixable in isolation.

### D4. Open-close levels are priced at the midpoint of the body overlap

`detect_open_close_level()` returns `(overlap_lo + overlap_hi) / 2`.
Bishop describes the level as where *"price closed at this particular
area and then opened again at this same level where it closed"*
(bias-1 t=120) and draws it as a line at that boundary.

For gapless consecutive candles these are **the same number** — the
overlap collapses to a point at the shared close/open. They diverge
only when the bodies genuinely overlap, where the midpoint is a
reasonable but unstated choice. Left alone; noted because a future
reader will otherwise assume the boundary.

### D5. `min_reward_r = 1.0` can skip trades the taught rule takes

The taught target is the liquidity, whatever it is worth. Under
`erl_mode="target"`, an ERL nearer than 1R makes the trade get skipped.

This is not a mis-reading — it came from a direct instruction ("a trade
of less than 1R doesn't make sense to hold") and is a deliberate house
rule. Recorded so the two are not later mistaken for each other.

### D6. The stop width fallback anchors to the level being entered at

`_natural_stop_too_wide()` falls back to `origin_stop_loss(new_key_level
.price)`. On aggressive style the entry price **is** the key level, so
the fallback collapses toward a ~1-pip stop — the live EURGBP
`INVALID_STOPS` rejection of 2026-09-01.

`open_close` was wired into that same fallback for consistency with the
existing branches. `breakout`/`sweep_break` were not: they anchor to the
reaction leg extreme with no width test, which is the invalidation-zone
rule. That inconsistency is deliberate but it means the four taught
triggers do not all treat stop width the same way.

### D7. 5.3 says the inducement candle must NOT tap the level

*"the next one hour or 30 minutes candle is going to trade very close to
the V shape or the A shape key level. But it's not going to tap into
it"* (video-14).

The entry loop's touch test is `prev OR curr` spanning the level, so a
setup where the **previous** candle tapped still qualifies. That is
looser than taught. Left because tightening it changes the shipped
triggers' numbers too, and this run is not the place to do that.

## What this changes about the pending A/B

Nothing about the plan, but two things about how to read it.

1. B2 means any earlier reasoning about "how often will the new triggers
   fire" was worthless — they could not fire at all.
2. D3 means `compare_triggers` is measuring more than the trigger
   patterns. The taught set changes which candles are classified, which
   changes `entry_pattern`, which changes the `irl_mode` path if it is
   ever enabled. Read the per-trigger breakdown first, as the tool's own
   output says.
